# Sieve-Order v1.1.0

**AIプロンプト観測エンジン**

*Sieve-Order は、AIへのプロンプトを可視化するための道具です。プロンプトの文中に含まれる観測可能な構造をレシート形式で出力します。*

> 自由記述プロンプトを「AIへの注文」として、決定論的・ゼロ依存・説明可能な形で観測し、
> その結果を人間とAIの双方に「レシート」として返すエンジンです。

[Sieve](https://github.com/neguseatama/sieve-core) シリーズを、**AIへの注文構造**という領域へ拡張しました。

> v1.0では「何を観測し、何を観測しないか」という境界を確定しました。  
> v1.1では、その同じ観測モデルに英語の表層語彙を追加しています。意味解釈は追加していません。

---

## 💡 コンセプト

このプロジェクトでは、自由記述プロンプトをファーストフード店への注文にたとえます。

- **注文** — ユーザーが自由に書いたプロンプト
- **メニュー** — Observerが観測可能なREQUEST / ACTION / TARGETの語彙集合
- **注文票** — 入力から観測された注文構造
- **レシート** — 注文票と6軸の観測結果

例えば、

`資料を確認してください。`

は、次の注文として観測されます。

```text
REQUEST = REQUEST
ACTION  = 確認
TARGET  = 資料
```

英語でも同じモデルを使います。

`Please check the document.`

```text
REQUEST = REQUEST
ACTION  = check
TARGET  = document
```

REQUEST表現は一つの集合として正規化します。丁寧さ・強さ・善悪などの順位付けは行いません。

**Observerは、足りない部品を補完したり、ユーザーの意図を推測したりしません。** 現在の規則で観測できるメニュー部品と関係だけをレシートに載せます。

---

## 📐 6-bit 観測空間

| 軸 | 名称 | 観測内容 |
|------|------|----------|
| H2 | REQUEST | 依頼・命令表現の表層 |
| H3 | ACTION + TARGET | 明示的な局所表層関係 |
| H4 | Instruction Hierarchy | 指示階層干渉の明示表現 |
| H5 | External Rule Match | 外部から与えられたルール式への一致 |
| H6 | Obfuscation Surface | 不可視制御文字・Base64様表層パターン |
| H7 | External Reference | URL・ファイル参照表層パターン |

マスク表記：`H2H3H4H5H6H7`（例：`110000`）。

`0` は「存在しない」の証明ではなく、現在の規則で証拠が観測されなかったことを意味します。

---

## 🍔 メニュー

注文の最小メニューは3種類です。

- **REQUEST** — 日本語・英語の依頼／命令表現の表層。
- **ACTION** — あらかじめ定めた、意図的に小さくした行為語彙。
- **TARGET** — あらかじめ定めた、意図的に小さくした対象語彙。

メニューは意味理解のための分類器ではありません。見つかった部品だけをレシートに載せ、足りない部品は補いません。

### H3：局所的な表層関係

H3は、言語ごとに定めた表層規則で観測します。

- 日本語：`TARGET + 助詞 + ACTION`（例：`資料を確認`）
- 英語：`ACTION + 表層上の接続語 + TARGET`（例：`check the document`）

並列TARGETを意味的に展開したり、複数の注文をまたいで意味的な関係を復元したりはしません。

英語H3は、日本語の対応する表層規則よりも、通常の叙述文に反応しやすい場合があります。これは現在の語彙的な観測方式が持つ性質であり、意味分類の精度を保証するものではありません。

---

## 🧾 レシート

同じ `Observation` から2種類の表現を作ります。

1. **Human Receipt** — 人間が確認するためのレシート
2. **Machine Receipt** — AIやソフトウェアが扱える構造化データ

両者の観測事実は同一です。人間用だけに判断を追加したり、AI用だけに観測結果を隠したりしません。

### Evidence Locations

元入力が利用可能な場合、Human Receiptは既存Evidenceの`start`/`end`と周辺文脈を`EVIDENCE LOCATIONS`として表示できます。これは既存Evidenceへ戻るための表示であり、観測の追加ではありません。周辺文脈から否定・引用・意図・実行スコープなどを意味解釈しません。

---

## 🔍 H5の境界

H5は、外部から与えられたルール式との一致だけを観測します。

例えば「認証情報」というルールがある場合、

`これは認証情報ではありません。`

でも文字列一致は観測されます。これは「認証情報である」という意味判断ではありません。

---

## ⚠️ 観測外

本バージョンでは、以下を判定・推測しません。

- intent
- legality
- morality
- maliciousness
- external-claim truth
- model-specific token count
- H3の意味的な関係展開（並列TARGETの追加関係化を含む）
- 引用・例文・説明対象テキストの実行スコープ
- 複数注文にまたがるACTION/TARGETの意味的な対応付け

これらは単に「まだ実装していない機能」ではなく、観測範囲として明示的に含めないと決めた境界です。

---

## 🌐 対応言語

Sieve-Order v1.1.0が対応する表層語彙は、次の2言語のみです。

- 日本語（`ja`）
- 英語（`en`）

言語判定や翻訳は行いません。

英語の語形変化も意図的に補完しません。例えば、固定メニュー項目 `check` から `checking` や `checked` を自動的に観測することはありません。

## 🔥 主な特徴

- **6-bit 観測空間（H2〜H7）**  
  明示的に定義した表層信号を独立・決定論的に観測します。
- **ゼロ依存**  
  Python標準ライブラリのみ。オフラインで動作し、テレメトリを行いません。
- **決定論**  
  同じ入力・ルール・設定からは同じ観測結果を返します。
- **説明可能性**  
  Evidenceに観測された文字列と再現可能な文字位置を付与します。
- **観測であって判定ではない**  
  注文が善い・悪い・合法・違法・悪意がある・安全である、などとは宣言しません。
- **Human Receipt / Machine Receipt**  
  どちらも同じ `Observation` から生成します。
- **日本語 + 英語**  
  v1.1.0では、この2つの表層語彙だけを正式対応します。
- **境界優先の評価**  
  実世界の正解率を目的にせず、境界例を回帰テストとして固定します。

## 📦 インストール

```bash
pip install .
```

コア実装の実行時依存はPython標準ライブラリのみです。

---

## 💻 クイックスタート

```bash
python -m sieve_order "Please check the document."
python -m sieve_order --json "Please check the document."
```

日本語もそのまま利用できます。

```bash
python -m sieve_order "資料を確認してください。"
```

## 🔬 テスト

```bash
python -m unittest discover -s sieve_order/tests -v
```

テストスイートでは、決定論性、レシートの投影、日英それぞれの境界、メタデータ整合性、仕様不変条件を確認します。実世界の精度ベンチマークではありません。
